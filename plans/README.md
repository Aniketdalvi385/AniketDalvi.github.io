## Recommended order

**1 → 2 → 3 → 4 → 5**, by leverage.

- **001 first.** It is the highest-frequency motion on the site: the underline
  state changes continuously during ordinary scrolling, so it is the change most
  visitors will actually notice. Self-contained, one file.
- **002 then 003.** Both are in `Contact.astro` and both touch the script block,
  so doing them back to back avoids re-reading the same file. 002 is the more
  valuable of the two (an error nobody notices is a usability problem; a
  confirmation without a flourish is only a missed moment).
- **004 late, deliberately.** It rewrites 42 curve literals across 12 files. Run
  it *after* 001–003 so those plans' new curves are swept up in the same pass —
  running it first means the three new rules immediately reintroduce literals.
- **005 last.** Pure polish, no dependency either way.

## Dependencies

- **004 depends on 001, 002, 003** only in the sense of ordering: each of those
  adds new `cubic-bezier(...)` literals that 004 should tokenise. If 004 runs
  first, re-run its Step 2 sweep afterwards.
- **005 references `cubic-bezier(0.34, 1.56, 0.64, 1)`.** If 004 has already
  landed, use `var(--ease-spring)` instead; the plan says so inline.
- 001, 002, 003 are mutually independent.

## Conventions these plans follow

Pulled from the existing code, not invented:

- **`cubic-bezier(0.16, 1, 0.3, 1)`** — the standard out-curve for pointer
  feedback and reveals. 38 uses.
- **`cubic-bezier(0.76, 0, 0.24, 1)`** — full-page veils and the loader wipe.
  A symmetric ease-in-out, correct for on-screen travel rather than pointer
  feedback. 3 uses.
- **`cubic-bezier(0.34, 1.56, 0.64, 1)`** — the single deliberate overshoot,
  used only by `.send` on hover. 1 use.
- **Durations are per-component, not a scale.** CLAUDE.md documents the budget:
  0.2s hover feedback, 0.5s theme crossfade, 0.8s reveals with 70ms stagger,
  0.9s metrics curtain, 0.7–0.82s page veils.
- **Reduced motion means gentler, not absent.** The global block in
  `global.css` suppresses transform via `.hov-lift` / `.hov-shift` while keeping
  colour and shadow fades.

## Verification notes that apply to every plan

- **Astro splits CSS.** A rule may land in `dist/_astro/*.css` **or** in an
  inline `<style>` block in each HTML file. Checking only the external bundle
  will report rules as missing when they shipped fine.
- **Headless Chrome does not run CSS transitions** under
  `--virtual-time-budget`, and IntersectionObserver does not fire there either.
  Verify end-states and computed values headlessly; feel-check motion in a real
  browser.
- `npm run build` runs `astro check` first, so a type error fails the build.
